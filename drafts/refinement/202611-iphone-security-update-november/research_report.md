# Research Report

## 調査結論

Appleの公式文書で、**iOS 27.2.1・26.7.3・18.7.12の公開日は2026年11月9日**と確認した。iPhoneの対象表記は、27.2.1と26.7.3が「iPhone 11以降」、18.7.12が「iPhone XS／XS Max／XR」。採用情報と一致する。[Appleのセキュリティリリース一覧](https://support.apple.com/en-us/100100)

読者には、**設定→一般→ソフトウェアアップデートで更新を確認する**行動を前半に示す。Appleが案内する事前準備は、バックアップ、電源への接続、Wi-Fi接続。[Appleの更新手順](https://support.apple.com/en-us/118575)

更新を早めに確認する理由は、接続やメッセージなどに関わる安全上の問題が修正されたため。各問題の成立条件を残し、「すべてのiPhoneが侵害された」「悪用が確認された」とは書かない。今回確認した3文書には、実際の悪用を把握している旨の記載は見当たらない。これは悪用が存在しないという確認ではない。[27.2.1の安全更新内容](https://support.apple.com/en-us/149715)、[26.7.3の安全更新内容](https://support.apple.com/en-us/149716)、[18.7.12の安全更新内容](https://support.apple.com/en-us/149717)

### F3. 攻撃条件は問題ごとに異なる

Bluetoothの届く範囲という条件を、インターネット越しの無条件な攻撃に広げない。同じネットワークという条件を、必ず同じWi-Fiに限るとも言い換えない。MediaRemoteの項目では物理アクセスが条件になっている。[18.7.12の条件記載](https://support.apple.com/en-us/149717)

一方、Messagesには遠隔の攻撃者に関する項目もある。「近くにいる攻撃者だけの問題」と全体をまとめない。また、特定のグループ参加・閲覧の問題を「全メッセージが盗まれる」と拡大しない。[26.7.3のMessages記載](https://support.apple.com/en-us/149716)

### F4. 悪用について確認できた範囲

今回取得した3つの個別文書には、Appleが実際の悪用を把握しているという注記を確認できなかった。記事で使える表現は、**「今回確認したAppleの説明には、実際の悪用に関する記載は見当たらない」**までとする。[27.2.1](https://support.apple.com/en-us/149715)、[26.7.3](https://support.apple.com/en-us/149716)、[18.7.12](https://support.apple.com/en-us/149717)

「悪用なし」「被害ゼロ」「ゼロデイ攻撃が発生」とする根拠は得ていない。

### F5. 更新前の準備と更新操作

Appleの案内は次の順序になっている。[公式更新手順](https://support.apple.com/en-us/118575)

1. iCloudまたはコンピュータでバックアップする。
2. iPhoneを電源につなぎ、Wi-Fiでインターネットへ接続する。
3. 「設定」→「一般」→「ソフトウェアアップデート」を開く。
4. 現在のiOSと更新の有無を確認し、更新があれば画面の案内に従う。

同資料は自動更新の設定も案内している。自動インストールは、充電中かつWi-Fi接続中の夜間に行う仕組みとして説明されている。自動更新を有効にしたことだけで、今回の版への更新完了を確認したことにはならない。[自動更新の説明](https://support.apple.com/en-us/118575)

第三者報道や関係者発言は今回の根拠として採用していない。以下は公式事実から導く編集判断であり、Appleの直接発言として引用しない。

| 判断 | 根拠・扱い |
|---|---|
| 「今、設定を開いて更新を確認する」と勧める | 修正版が公開済みで、Appleもソフトウェアを最新に保つ重要性を案内している。緊急の被害発生を確認したという意味にはしない。[Appleの案内](https://support.apple.com/en-us/100100) |
| バックアップ・電源・Wi-Fiと操作経路を前半に置く | 読者が行動できる説明を優先する編集判断。手順自体は公式資料に基づく。[更新手順](https://support.apple.com/en-us/118575) |
| 件数より、対象機種と条件の違いを重視する | 9件・8件・6件だけでは、利用者ごとの危険度や版ごとの安全性を比較できない。 |

## 後続工程への引き継ぎ

読者向けには、「iPhoneの安全上の問題を直す更新が出た」という一文から始める。専門語は、脆弱性なら「安全上の弱点」、ペアリングなら「機器同士を接続するための登録」、CVEなら「安全上の問題を識別する番号」と短く説明する。

本文図解8枚へ渡せる調査論点は、①何の更新か、②対象機種、③バックアップ・電源・Wi-Fi、④設定での確認、⑤近距離・同一ネットワーク・物理アクセスの違い、⑥メッセージに関する修正、⑦件数と悪用情報の読み方、⑧更新後の確認と自動更新。別サムネイルでは、端末の更新を確かめる行動を主題にし、侵害済みと受け取れる演出を避ける。
