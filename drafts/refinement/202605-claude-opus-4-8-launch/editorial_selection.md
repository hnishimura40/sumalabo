# 2. Editorial Selection

## 採用する論点

### 1. Opus 4.8 は「AIに仕事を任せる方向」のアップデート
単に「賢くなった」ではなく、  
**長い作業を分解する、並列で調べる、ツールを使う、検証して返す**  
という流れが強くなったアップデートとして整理する。

読者向けの言い換えは、  
「チャットで答えるAI」から「作業を段取りして進めるAI」への一歩。

### 2. Dynamic workflows を中心に据える
今回のニュースで一番わかりやすい変化は Dynamic workflows。  
「数百のサブエージェント」という言葉だけだと難しいので、記事では次のように噛み砕く。

- 1人のAIが全部を順番にやるのではなく、作業を小分けする
- 複数の担当AIに並行して調べさせる
- 最後にまとめて検証する
- 大規模コード修正や長い調査に向く

ここは記事の中核にしてよい。

### 3. Effort control は「考える深さの切り替え」として説明
専門用語を避け、  
「軽い質問は速く、重い作業は深く」  
という軸で説明する。

ただし「利用者が必ず安く使える」とは書かない。低 effort は rate limit 消費を抑えやすいという程度にする。

### 4. Messages API の途中 system は開発者寄りだが、意味は説明する
ここは読者によっては難しいが、Opus 4.8 の方向性を示す重要要素。  
本文では短く、

「AIに長い仕事を任せている途中で、追加ルールや条件を差し込めるようになった」

と説明する。

細かい API 実装は深掘りしない。

### 5. adaptive thinking は「考えるべき場面だけ考える」
「推論トークン」などの専門語は最小限にする。  
AIが毎回全力で長考するのではなく、必要に応じて考え方を切り替える、という説明にする。

### 6. honesty / 不確実性の申告
すまラボ向けにはかなり重要。  
「AIが強気に間違える」問題を減らす方向として扱える。

ただし、「ハルシネーションがなくなった」とは書かない。  
表現は、

- 根拠が薄いときに慎重になりやすい
- 自分の作業の不確実さを示しやすい
- コードの欠陥を見逃しにくくなった

程度にする。

### 7. computer-use / browser-agent の強化
Online-Mind2Web 84% は、ブラウザ操作・画面操作系の進化を説明する補助数字として採用する。  
ただしベンチの詳細解説に寄せすぎない。

読者向けには、

「ウェブ画面を見ながら手順を進めるAIエージェントの精度が上がっている」

という意味づけにする。

### 8. GitHub Copilot GA
開発者向けの話だが、Opus 4.8 が単なる発表にとどまらず、GitHub Copilot にも展開されている点として採用。  
記事内では補足扱い。

### 9. Claude Mythos Preview は最後に軽く触れる
Opus 4.8 の先に、さらに高知能な Claude Mythos Preview が控えている、という流れはニュース性がある。  
ただし主役にしない。  
「Anthropicはさらに上位のモデルも準備しているが、安全対策が前提」というまとめ方にする。

## 採用しない論点

### 1. 「最大1,000サブエージェント」
公式とズレる可能性があるため採用しない。  
本文では「数百」に統一。

### 2. 公式確認できないベンチ数字の羅列
SWE-Bench Pro、OSWorld、fast mode 速度比較などは、記事が開発者向けベンチ記事に寄りすぎるため主軸にしない。必要があっても脚注的な扱いまで。

### 3. 「4.7が不評だったから急いだ」
公式見解ではないため採用しない。  
TechCrunch の競争環境への言及は、背景として薄く使う程度。

### 4. 投資・企業分析
Anthropic の資金調達、企業価値、競合企業の株価影響などには寄せない。  
すまラボの記事テーマから外れる。

### 5. 日本での提供詳細の断定
日本語対応、国内プラン別の利用可否、円換算価格は断定しない。  
必要なら「日本向けの細かな条件は確認が必要」とする。

## 主役にする論点

**主役は、Claude Opus 4.8 が「チャット回答の精度向上」だけでなく、AIに大きな仕事を任せるための土台を強化したこと。**

具体的には、

1. Dynamic workflows  
2. Effort control  
3. adaptive thinking  
4. 途中 system  
5. honesty / 不確実性の申告  
6. computer-use / coding / knowledge work の改善

この順番で組むと、ニュースの構造が伝わりやすい。
