# Editorial Selection

出所: research_report.md / 2026-09-24 JST

## 採用する事実

- 公式発表にある、Pro・Max・Teamの5時間利用上限の引き上げ。
- subscription usersへ、保存して好きな時に使えるrate limit resetを提供すること。
- リセット対象は、表示された種類に応じて5時間枠または週次枠のどちらかであること。
- Web版／Claude Desktopで適用し、Mobile／Claude Codeにはボタンがないこと。
- 取り消し不可、期限表示あり、通常の週次リセット日時は動かないこと。
- 返金やusage credits残高の変更ではないこと。

## 限定採用する主張

- 「今すぐ使わない」理由は人数の話にせず、一度使うと戻せない仕組みから導く実用判断として扱う。
- 「無料で全回復」は、対象の枠が満タンへ戻るという意味に限定する。5時間枠と週次枠の同時回復とは書かない。
- 10月22日という日付は本文の確定情報にしない。自分のUsage画面の表示を優先する。

## 不採用

- 「多くの人が温存している」という定量根拠のない一般化。
- 5時間枠と週次枠が必ず同時に回復するという説明。
- 全プラン・全地域へ同条件で配られたという断定。
- 公式に出ていない上限増加率。

## 確度区分

### facts

- limit resetは、対象プランに時折付与され、表示された対象枠を満タンに戻す。
- Settings > Usageで対象・期限を確認し、Web版またはDesktopから使う。
- 使用後は取り消せず、通常の週次リセット日時は変わらない。

### claims

- スカウト元は「両方の上限を無料で1回だけ全回復」と要約しているが、公式説明より範囲が広い。

### uncertain

- 各アカウントの対象枠、付与対象、失効日時、5時間枠の具体的な増加率。

## 読者翻訳設計

- 主題の一言説明: Claudeの利用枠を、待たずに一度だけ満タンへ戻せる無料ボタンが一部の契約者に表示される話。
- 関係がある人: Claude Pro・Max・Teamなどを契約し、5時間枠や週次枠で作業が止まることがある人。
- あまり関係がない人: 無料プランだけを使う人、上限へほとんど達しない人、Claude APIのレート制限だけを調べたい人。
- 専門用語:
  - limit reset → 利用枠を満タンへ戻す一度きりの無料の仕組み
  - 利用上限 → Claudeへ一定時間に頼める仕事量を区切る仕組み
  - usage credits → 契約枠を超えて使うための別料金の仕組み
  - Claude Code → ターミナルやIDEから開発作業を頼む機能
- 事実から言えること: 表示された対象枠は、押した時点で満タンへ戻る。上限到達前でも使える。WebかDesktopで操作後、共有枠は同じアカウントの他のClaude製品にも反映される。
- 事実から言えないこと: 全員にある、両方の枠が同時回復する、期限が全員同じ、上限が無制限になる、すでに払った追加料金が返る。

## 記事の主軸

「押せば得」ではなく、「まず対象枠と期限を確認し、必要な停止場面まで温存する。ただし失効忘れは避ける」という判断を、初めて聞く人にも分かる順序で説明する。
