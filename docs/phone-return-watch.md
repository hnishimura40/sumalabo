# スマホ最安値定点観測の運用

初回は iPhone 18 Pro 256GB。本文は `content/articles/iphone-18-pro-return-price-watch.mdx`、価格と出典は `data/phone-return-watch.json` に保存する。機種・容量ごとに `offerId` が同じ販売経路の記録を時系列で追加する。機種や容量の追加は同じ計算と表示部品を使う。価格表と推移は正本から描画する。

## 毎日の調査

1. 別作業ツリーで最新の `origin/main` を取得する。現在の掲載行と、公式キャリア5社・量販店6社・既知の地域別案件を確認する。
2. `node scripts/automation/phone-return-watch.mjs check logs/scout/phone-return-watch/official-sources.json` を実行する。ハッシュは巡回結果の記録。終了コード2には取得できないURLがある。公式ブラウザーで機種、容量、申込経路、MNP、分割を選んで補完する。量販店公式チラシ・店舗告知を優先する。報道やSNSは候補に使い、店舗・日付・適用条件を公式情報で裏付ける。
3. 調査時の表示、掲載日時、機種、容量、販売経路、在庫、申込・維持条件、期限、返却料・事務手数料・必須費用を照合する。分割額の値引きは適用済みの値で保存する。条件付きポイントは支払額に入れない。取得不能は `unconfirmed`、公式に終了を確認したものは `ended` とし、理由と参照先を保存する。
4. 調査結果を `logs/scout/phone-return-watch/reviewed.json` に `{ "observations": [...] }` で保存し、`node scripts/automation/phone-return-watch.mjs append <reviewed.json>` で検証する。1万円以上動いた行は別の公式根拠と確認理由を `recheckUrl` と `recheckReason` に記録する。合格した結果に `--apply` を付けると追記する。変更のない日も確認できた根拠と日時を蓄積する。
5. 期限内・48時間以内の確認済み行を現在欄に表示する。順位は次回に他社へ移る場合の端末関連総額。回線料・条件付きポイント・査定追加費用・次の端末の価格は別に扱う。確認できない値をゼロとして扱わない。買い替え免除は公式条件を保存した同一キャリアのケースだけに反映する。
6. 価格・条件の照合と計算監査、単体テスト、記事ゲート、秘密情報検査、ビルドを通す。表示変更がある場合は375pxとPCの明暗表示を確認する。対象を絞ったPRを作り、最新main・headのハッシュ・mergeableを確認してマージする。最新mainのクリーンcheckoutで `npm run deploy:production -- --slug=iphone-18-pro-return-price-watch --trigger=manual --run-mode=maintenance --output=<private-result.json>` を実行。HTTP 200・strict verify・HTML上の確認日時と掲載金額を照合し、公開できた履歴の日時とPRを非公開記録に残す。失敗時は公開済み扱いにせず次回も確認する。

## 毎朝8時の定期実行

対象はスマホ最安値定点観測の iPhone 18 Pro 256GB。携帯キャンペーンを確認する既存の実行に同居し、調査結果・公開確認はそれぞれ記録する。価格・条件に変化がなくても当日照合できた事実を履歴に追記し、記事の最終調査日時まで更新する。価格・制度の意味のある変化や新しい取得障害、公開失敗を報告し、金額不変の確認日時更新は定例通知しない。

2026年11月28日の明示承認は本ページの日次保守とその本番反映が対象。日次の変更範囲は `data/phone-return-watch.json` と、内容・検品に必要な当該記事と編集記録。観測が既に公開済みか履歴・確認日時を照合し、同じ観測を重複して追記しない。4:30の既存夜間実行やOSタスクは変更しない。

比較ページのCPU表記とGeekbenchの出典は `data/mobile-device-benchmarks.json`。版の異なる点数や他の機種・CPUで測った点数を補完に使わない。集計と個別公開測定を区別する。散布図は現行の乗り換え一括額だけを使用し、未確認のCPU点数は空欄として扱う。

## 派生記事

- **広告の価格と返却総額**。返却料・同社での買い替え免除・次回支出を解説。ハブは実測値を担当。
- **査定される傷の境界**。査定基準、機種別の追加負担、補償有無を比較。体験談は公式基準と区別。
- **いつ安くなるか**。日付付き過去データが揃った時点でシーズン別に分析。ハブは最新比較と推移を担当。
- **povoから移る**。povo1.0・2.0別の対象、移行手順、乗り換え前後の回線料を解説。
- **返却と一括の分岐点**。保有期間、残存価値、回線料差を比較。
- **補償を付けるか**。保険料と免責額、故障時負担の上限を比較。
- **返却前チェックリスト**。端末の状態、アカウント解除・初期化、期限、発送記録を整理。

各記事から該当する総額・査定・価格推移へ直接リンクする。ハブは公開済みの派生記事へのリンクを段階的に追加する。
