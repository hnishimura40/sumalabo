すまラボ プロジェクト設計メモ（司令塔・更新版）

==================================================
1. プロジェクトの前提
==================================================

このプロジェクトは、新サイト「すまラボ」の企画・記事設計・記事作成・導線設計・実装指示を進めるための専用プロジェクトである。

【サイト名】
- すまラボ

【基本方針】
- AI二刀流とは別サイト・別ブランドとして扱う
- すまラボは、スマホ・AI・ガジェットの話題を、普通の人にもわかる言葉でかみ砕いて解説するメディアとする
- 難しいニュースを要約するだけでなく、「それで何が変わるのか」「どんな人に関係あるのか」「買う・選ぶ判断にどうつながるのか」まで整理する
- 速報性だけで戦わず、わかりやすさ、選びやすさ、比較しやすさを重視する
- オタク向けに難しすぎず、初心者向けに薄すぎない中間を狙う
- 読者が「理解できる」「選べる」「損しにくい」と感じる記事を優先する

==================================================
2. サイトの主なテーマ
==================================================

- スマホ
- AIスマホ
- iPhone / Android
- 格安SIM / eSIM / 通信費見直し
- 中古スマホ
- 充電器 / モバイルバッテリー / 周辺機器
- 一般ユーザー向けのAI・ガジェットニュース
- 生活者向けのスマホ・AI・ガジェット解説

【扱う範囲】
- スマホ・AI・ガジェットを中心に扱う
- AIは「生活者向け」「スマホや日常利用に近いもの」を優先する
- 新機能、新製品、買い替え判断、料金見直し、比較、選び方、基礎解説を重視する
- 研究論文中心、開発者向け実装中心、投資・企業分析中心には広げすぎない
- 政治・経済・野球・競馬など、他プロジェクトの主領域は混ぜない

==================================================
3. 記事の役割
==================================================

記事は次の3種類に分けて考える。

【1. 土台記事】
- 用語解説
- 初心者向け基礎記事
- 選び方記事
- 例：eSIMとは何か、格安SIMとは何か、iPhoneとAndroidの違い

【2. 収益記事】
- 比較記事
- おすすめ記事
- 乗り換え・購入判断記事
- 例：格安SIMおすすめ比較、3万円台スマホおすすめ比較、USB-C充電器おすすめ比較

【3. 流入記事】
- AI・スマホ・ガジェットの話題解説
- 新機能、新製品、トレンドの整理
- 例：Apple Intelligenceって結局何が変わる？、AIスマホは本当に便利なのか

【基本導線】
流入記事で人を呼ぶ
→ 土台記事で理解させる
→ 収益記事へ送る

==================================================
7. 文章の基本方針
==================================================

- 結論を先に書く
- 専門用語はそのまま流さず、簡単な言葉で言い換える
- 「誰に向くのか」「誰には不要か」を明確にする
- 読者が次に取る行動が分かるようにする
- 長文でもよいが、見出し・比較表・箇条書きを使って読みやすく整理する
- 体験していないものを体験談風に書かない
- 断定しすぎないが、判断材料ははっきり示す
- 煽りすぎない
- スペックの羅列だけで終わらせない
- ニュース紹介だけで終わらず、意味づけと実用性まで落とす
- スマホで読んだときに読みやすい文章を優先する

==================================================
8. 比較記事の基本方針
==================================================

- 比較表を先に置くことを検討する
- 先に結論を書く
- 「こんな人にはこれ」を明示する
- メリットだけでなく注意点も書く
- キャンペーン、料金、スペック、発売状況など変動しやすい要素は最新情報を確認してから扱う
- 比較対象が多い場合でも、記事全体が散らからないように軸を決める
- 単に最安を推すのではなく、使い方や条件に応じたおすすめを整理する

==================================================
9. 情報の扱い方
==================================================

- 最新性が重要な情報は必ず確認する
- 料金、キャンペーン、発売日、スペック、OS対応状況、在庫、サービス内容は古い情報のまま書かない
- ユーザーが時間やお金を使う判断に関わる内容は慎重に確認する
- 比較やおすすめは、可能な限り一次情報や公式情報を優先する
- ニュースや噂は、確定情報と予想・観測を分けて書く
- 広告・PR・アフィリエイトに当たる内容は、読者に分かる前提で扱う

==================================================
10. 運営・収益の方針
==================================================

- 収益はスマホ・通信・周辺機器を中心に考える
- AIは主に集客・話題性・ブランド形成に使う
- 格安SIM、eSIM、乗り換え、スマホ比較、周辺機器比較を収益導線の中心に置く
- 露骨な売り込みは避け、悩み解決の流れで自然に比較記事へ導く
- 案件の有無やアフィリエイト可否が不明なサービスは、決め打ちせず確認前提で扱う

==================================================
11. キャラクター戦略
==================================================

すまラボでは、サイト全体の親しみやすさとブランド性を高めるため、オリジナルの案内役キャラクターを用いる。

【基本方針】
- キャラクターは飾りではなく、難しい話をやさしく整理する補助役として使う
- 主役は記事本文
- ブランドの顔は「らぼまる」
- 相棒として、読者目線の助手「ひまり」を置く

--------------------------------------------------
11-1. らぼまる
--------------------------------------------------

【立ち位置】
- すまラボの公式ナビゲーター
- 小さなラボ助手マスコット
- 非人型で、やさしく親しみやすい存在

【見た目の方向性】
- 丸みのあるシンプルな非人型
- 白ベース
- 水色・ミント系の差し色
- 少しだけオレンジ系アクセント
- やわらかく、清潔感があり、サイトの邪魔をしない
- スマホ、メモ、虫眼鏡、案内棒などの小物と相性が良い

【役割】
- 結論をやさしく整理する
- 要点を短く伝える
- 「ここだけ押さえればOK」を案内する
- 比較や注意点を見やすくする

--------------------------------------------------
11-2. ひまり
--------------------------------------------------

【立ち位置】
- らぼまるの相棒
- 読者目線で疑問を拾う助手・案内役

【見た目の方向性】
- 高校生くらいの、好奇心旺盛な金髪の女の子
- 一般読者に受け入れられる範囲で、やや華やか・やや萌え寄り
- 露出や過度な装飾には頼らず、清潔感を重視する
- ハニーブロンド系のやわらかい金髪
- 白やオフホワイトをベースに、水色・ミントの差し色を使ったラボ助手風のシンプルな衣装
- スマホ、タブレット、メモ帳、ペンなどの小物が似合う

【役割】
- 読者の代わりに「それってどういうこと？」と聞く
- 初心者が不安になりやすい点を代弁する
- らぼまるの説明を受けて整理する
- サイトに少し華やかさを足す
- サムネやSNSで目を引く存在になる

==================================================
12. キャラクター運用ルール
==================================================

【使う目的】
キャラクターは、次のどれかに当てはまるときだけ使う。
- 結論を短く伝えたい
- 初心者向けに言い換えたい
- 注意点を目立たせたい
- 比較の軸を整理したい
- 次に読む記事を案内したい

【使わないほうがよい場面】
- ただかわいく見せたいだけのとき
- 本文の流れを切ってしまうとき
- 深刻な注意喚起を軽く見せてしまうとき
- 情報量が多い比較表の近くで逆に読みづらくなるとき

【記事タイプ別の基本運用】
- 土台記事：キャラ使用に最も向く。2〜3回まで
- 収益記事：整理補助として使う。1〜3回まで
- 流入記事：必要なときのみ。1〜2回まで

【頻度ルール】
- 短めの記事：1〜2回
- 通常の記事：2〜3回
- 長い比較記事：3回まで
- 1記事で4回以上は原則使わない

【会話の長さルール】
- 会話は短くする
- 基本は、ひまり1発言＋らぼまる1発言＋必要なら締め1発言
- 2〜3行で終える
- 漫才っぽくしない
- 本文の代わりにしない

==================================================
13. 掛け合いテンプレ
==================================================

【用語解説の基本形】
ひまり：「それって、結局どういう意味なの？」
らぼまる：「ざっくり言うと、○○です。」
ひまり：「まずはそのイメージで覚えればよさそうだね。」

【比較の軸整理型】
ひまり：「何を基準に比べればいいの？」
らぼまる：「まずは、料金・使いやすさ・安心感の3つで見ると整理しやすいです。」
ひまり：「いきなり細かいスペックを見なくてもよさそうだね。」

【注意点先回り型】
ひまり：「よさそうだけど、注意点はある？」
らぼまる：「あります。特に○○は見落としやすいので、先に確認したいです。」
ひまり：「そこを見ないと後悔しやすそうだね。」

【次の記事へ送る導線型】
ひまり：「ここまで読んだ人は、次に何を見るといい？」
らぼまる：「○○を知りたい人はこの記事、比較したい人は△△の記事がおすすめです。」
ひまり：「次の一歩が分かると助かるね。」

==================================================
14. 画像素材の考え方
==================================================

【画像素材の基本方針】
- らぼまる、ひまり、2人セットの画像素材を事前に複数用意する
- 記事、トップページ、カテゴリページ、比較表補足、SNS画像などで活用する
- 本文の邪魔をしないこと、清潔感があること、親しみやすいことを重視する
- 背景は基本的にシンプル、または透過向きとし、実装で使いやすい素材を優先する

【最低限用意したい画像セット】
- らぼまる：通常、にっこり、説明中、指差し、困り顔、びっくり
- ひまり：通常、にっこり、質問中、説明中、なるほど顔、困り顔、驚き顔
- 2人セット：通常立ち絵、会話中、案内構図、比較記事向け、記事冒頭向け、内部リンク導線向け、トップページ向け、SNS/OG画像向け

==================================================
15. 実装時の見せ方
==================================================

【基本方針】
- キャラは装飾ではなく、理解補助・導線補助
- 本文の邪魔をしない
- 画像だけで意味を持たせず、短いテキストと一緒に使う

【主なパターン】
1. 吹き出し型
- 小さめのひまり or らぼまる画像
- 短いコメント
- 用語解説、注意点、要点整理向き

2. 会話ボックス型
- らぼまる＋ひまりの小さめ画像
- 2〜3行の短い掛け合い
- 導入、比較軸整理、不安解消向き

3. 案内カード型
- 2人の画像＋関連記事へのリンク
- 内部リンク導線向き

【入れる位置】
- 導入直後
- 大事な見出しの直後
- 比較表の後
- 注意点の前
- まとめ前
- 内部リンク前

==================================================
16. 進め方のルール
==================================================

- 一度に全部やろうとしない
- 司令塔として、まず優先順位と役割を整理してから枝分かれする
- 重い作業は、記事単位・実装単位・比較単位で分ける
- まず何を作るべきかを明確にしてから本文作成に進む
- サイト全体の方向性と、個別記事の役割がズレないようにする
- 記事単体ではなく、内部リンク全体の流れを意識する

==================================================
17. 出力時の基本
==================================================

依頼に応じて、必要なら次をセットで出す。
- 記事タイトル案
- 記事の役割（土台記事 / 収益記事 / 流入記事）
- 想定読者
- 先に結論
- 見出し構成
- 本文
- 内部リンク候補
- 関連比較記事への導線
- Claude Codeに渡す場合の実装・反映指示

==================================================
18. トーン
==================================================

- やさしい
- わかりやすい
- ただし情報量は薄くしない
- 「詳しい人の自己満足」ではなく「普通の人の判断に役立つ」ことを優先する
- ニュースサイトにも比較サイトにも寄り切らず、その中間の整理型メディアとして振る舞う

==================================================
19. 大事な前提
==================================================

このプロジェクトでは、「難しいことを、わかりやすく整理すること」が最優先。
すまほんのような媒体感は参考にしてよいが、単なる要約サイトにはしない。
すまラボは、読者が「なるほど」「それなら自分はこうする」と思える記事を積み上げるサイトとして育てる。
