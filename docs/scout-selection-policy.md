# 記事選定：AI主軸と過去の実績比較（2026-11-03）

AI記事を主軸とし、重要モデル・最新の性能指標・人気が急伸するAIアプリを取り逃さない。通信キャンペーンとおすすめ製品は、AI主軸に追加する柱として扱う。局地的な親子教室・催事を重要AIの代わりに採用しない。既存の一次情報確認、重複判定、品質ゲートは維持する。

携帯キャンペーンの毎日チェック・既存記事更新は、`docs/mobile-campaign-maintenance.md`に従う独立した保守作業とする。AI記事の新規選定1件の枠を使わず、公式条件の新規・変更・終了を確認する。2026-11-03のユーザー承認に従い、公式確認と検品を通った変更は、以後の確認を挟まずPRマージ・本番公開・公開検証まで自動実行する。

## 根拠と限界

GA4のページパス別・全流入の年初来実績を確認し、同じ7月公開の観測できた記事を比較した。規約・保存設定の混同、身近なサービスの値上げ、手数料還元の条件、作品に登場した技術の実現可能性が上位だった。一部AI記事の過去PVが低いことを、重要AIのモデル発表やベンチマークを一律に下げる根拠にはしない。2026-11-03のユーザー指示を優先し、AI主軸を明示する。

低調でも、題材だけが原因とは断定しない。配信経路、公開タイミング、見出し、計測開始時期が異なり、公開後7日を揃えた因果検証ではない。新着記事・実績に現れない記事を0PVとして評価しない。具体的なPVと比較結果はprivateな`logs/scout/selection-analysis-20261102/`に置き、公開リポジトリへ含めない。

## 採点

`data/automation/watch-sources.json`の`readerValuePolicy`を正本とする。複数の条件を同時に満たしたときだけ加点する。単に疑問形にする、人気ブランドを列挙する、無料や期限の語を入れるだけでは加点しない。

| 条件 | 加減点 |
|---|---:|
| Apple公式の無料総合ランキングで確認した上位・急上昇のAIアプリ | +40・優先度2 |
| AIの性能指標・ベンチマーク・リーダーボードの更新 | +36・優先度2 |
| AIの重要モデル・サービスの発表 | +24・優先度1 |
| 主要ニュース掲載または複数媒体掲載の根拠＋AIで深掘りできる具体的な疑問 | +32・優先度1（調査候補） |
| 局地的な親子教室・催事で、重要AIの根拠がない | -24 |
| 身近なサービス＋料金・規約・設定等＋具体的な変更 | +24 |
| 身近なサービス＋金銭的メリット＋適用条件 | +12 |
| 上記の変更・条件について、具体的な疑問・誤解を解消 | +8 |
| 作品・文化的話題＋技術＋実現できるかという疑問 | +26 |
| RSSに作品＋技術の接点があるが、まだ検証の疑問がない | +20（調査用の切り口を提案） |
| 身近な道具＋具体的作業＋実機・手順などの検証 | +12 |
| AIの限定利用枠・専門的な小更新で上記の価値がない | -16 |
| 発表・提供開始だけで上記の価値がない | -8 |

加点は合計+40、減点は合計-24まで。適格な候補の中では優先度2→1→0、その中で合計点順に並べる。鮮度は最大24、ブランドは1語3点・合計8点までに抑える。ブランド・発表などの一般語・インパクト語の合計も16点までとし、同じ見出しに語を足すだけで上位に来ないようにする。小さな実績から特定ブランドの全面優遇・全面除外はしない。

作品と技術の接点については、即時の行動変化がなくても、作品＋技術の2条件が揃い+20以上、既存criticalityが非負、総合点が閾値以上なら採用対象にする。実際の過去RSSでは、作品内AIの紹介から実現可能性の解説へ切り口を作っていたため、完成記事の疑問がRSSにも書かれていることは要求しない。`suggestedAngle`は調査提案であり、実現できるという事実認定ではない。海外限定除外・重複・除外カテゴリは迂回しない。検証する切り口を選んでも、未実施の実機検証を体験談として書かない。

## 自動運転への接続

身近なサービス・具体的な影響・変更内容の3条件が揃い+24以上の場合も、既存criticalityが非負、総合点が閾値以上なら採用対象にする。規約変更などを「設定」という単一語の旧加点8点だけで落とすことを避ける。海外限定・負のcriticalityの除外は維持する。

重要AIの性能指標・確認可能な発表・公式ランキングについては、即時の行動変化や日本での提供を必須条件にしない。旧criticalityでの「レポート」「調査」「海外限定」の減点があっても、根拠と総合点で適格にできる。未確認のモデル噂、一般の利用率アンケート、Metaの非AIハード発表はこの経路へ入れない。海外先行なら日本での利用可否を本文で説明する。

## 毎日のAI発見

選定の単位は企業名ではなく「話題のニュース × AIの視点で解ける読者の疑問」。ニュース本文にAIが登場することや、AIが事件の直接原因であることを要求しない。サイバー攻撃と防御、映像・音声の真偽、仕事・教育の変化、作品の技術の実現可能性、科学の予測・解析などを入口にする。企業名のリストを満たす条件や、特定企業専用の検索を使わない。切り口は設定の`newsAngleWatch.angleRules`で追加できる。

日本の主要ニュース全般・ビジネス・技術・科学・文化のRSSを日次スカウトへ追加し、AI語や企業名で収集を絞らない。Google Newsの主要フィード上位20件への掲載、または同時に取得した48時間以内の類似見出しが2媒体以上に載ることを注目の目安とする。媒体はRSSのsource URLまたは直接RSSの配信元ホストで区別し、Google Newsの代理URLや同じ媒体の複数フィードを2媒体とは数えない。類似見出しは語の一致による近似であり、転載元が独立した取材かは未検証。SNSのバズ・検索需要・急増を実測したと書かない。掲載順位・媒体・記事URL・公開日時・観測日時・AIの疑問を`newsTrend`に記録し、採用台帳・夜間工程へ引き継ぐ。

話題性だけではAI優先枠へ入れない。具体的なAIの疑問を提案でき、一次情報で説明を深められる題材を調査候補にする。話題の見出しに「AIなら？」を付けるだけのこじつけは不採用。AIが実際に使われたという事実と、AIの能力・限界からの解説を分ける。既存の鮮度・除外カテゴリ・重複判定を維持し、古い出来事を新着扱いしない。

既存の夜間スカウトで、日本と米国のApple公式無料総合ランキング100件を毎日取得する。既知のAI名に加え、AI表記のある新アプリも確認し、上位10位または前回比10位以上上昇かつ30位以内を候補にする。国、順位、提供元、確認日時、フィード更新日時を`appChart`に残す。ニュースが48時間以内でなくても、現在の順位観測に基づく未掲載の話題を拾う。観測日をサービス発表日へ置き換えない。

順位履歴はprivateな`logs/scout/ai-app-charts.json`へ保存する。取得失敗はsourceStatusへ残し、前回の記録を失敗データで上書きしない。初回観測から「連続首位」「ダウンロード急増」を断定しない。総合順位とカテゴリ順位、米国と日本、人気の指標と性能の指標を区別する。同じアプリの国違い・同順位で新記事を量産しない。

AIのニュース検索にはMeta・Muse・Llama・DeepSeekを加え、Artificial Analysis・LMArenaなどの性能指標を探す専用RSSも取得する。RSSは発見源であり、記事の指標値・測定条件・更新日は元のリーダーボードや公式発表に照合する。

`scout.mjs`の`scoreItem`で採点し、`isEligible`で判定する。候補JSONと採用台帳に、方針バージョン、加減点、根拠語、読者の疑問を残す。既報減点はその後に適用し、同じヒット記事の再投稿を促さない。

夜間runnerは開始時に`origin/main`へ同期する。昼間workspaceの変更だけでは反映完了ではない。正本のコードをPR経由でmainへ反映し、次回取得する同じコードであることを確認する。起動層・スケジュールは変更しない。
