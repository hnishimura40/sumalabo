# すまラボ 記事構成テンプレート

このドキュメントは、すまラボの記事をMDX化するときの標準構成を整理したものです。

土台記事の標準例は `content/articles/what-is-esim.mdx` です。今後の基礎記事では、この流れを基本形として使います。

## 共通ルール

- 結論を先に書く
- 1段落を長くしすぎない
- 専門用語は必ず言い換える
- 比較表、チェックリスト、カード型整理を使ってスマホで読みやすくする
- キャラクター使用は1記事1〜3回まで
- 未作成記事へは直リンクせず、MDXコメントで将来リンク候補を残す
- 料金、キャンペーン、発売日、在庫など変動情報は慎重に扱う

## 1. 土台記事 foundation

### 目的

用語、仕組み、選び方の前提を初心者にも分かるように整理し、次の比較・判断記事へつなげる。

例:

- `what-is-esim`
- `what-is-cheap-sim`
- `what-is-ai-smartphone`
- `iphone-vs-android`

### 想定読者

- 言葉は聞いたことがあるが、意味や違いが分からない人
- 買う、乗り換える、選ぶ前に基礎を知りたい人
- 詳しいスペックより、まず判断軸を整理したい人

### 推奨構成

1. 導入文
2. 30秒でわかる結論
3. `CharacterDialogue`
4. 基本解説
5. 比較表
6. メリット整理
7. 注意点チェックリスト
8. 向いている人 / 向いていない人
9. 関連テーマとの関係
10. `CharacterGuideCard`
11. まとめ

### 使うべき表・チェックリスト

- 用語A / 用語Bの違い
- 初心者が先に確認すべきこと
- 申し込み前、購入前、設定前チェックリスト
- 向いている人 / 向いていない人の2列表

### 推奨キャラクター部品

- 導入直後: `CharacterDialogue` + `duo_talk_half.webp`
- 注意点: `CharacterCallout` + `himari_question_icon.webp` または `labomaru_worried_icon.webp`
- まとめ前: `CharacterGuideCard` + `duo_guide_half.webp`

### 内部リンク導線

- 関連する土台記事へ横移動させる
- 理解が進んだ読者を収益記事へ送る
- 未作成記事はコメントで将来リンク候補として残す

例:

```text
eSIMとは何か
  -> 格安SIMとは何か
  -> 格安SIMおすすめ比較
  -> 楽天モバイルとahamoはどっち向き？
```

### 注意点

- 体験していない内容を体験談風に書かない
- 初心者向けでも、情報を薄くしすぎない
- キャラクター会話で本文を代替しない

## 2. 収益記事 revenue

### 目的

比較、購入、乗り換え判断を助け、読者が自分に合う候補を絞れるようにする。

例:

- `cheap-sim-comparison`
- `rakuten-mobile-vs-ahamo`
- `smartphone-under-30000-comparison`
- `usb-c-charger-comparison`

### 想定読者

- 基礎はある程度分かり、具体的に選びたい人
- どれがお得かではなく、自分に合うものを知りたい人
- 失敗しにくい比較軸を知りたい人

### 推奨構成

1. 導入文
2. 先に結論
3. 比較軸の説明
4. 比較表
5. 用途別おすすめ / 向いている人
6. 注意点チェックリスト
7. 迷ったときの選び方
8. 基礎記事への戻り導線
9. まとめ

### 使うべき表・チェックリスト

- 比較表
- 用途別おすすめ表
- 購入前 / 乗り換え前チェックリスト
- 向いている人 / 向いていない人

### 推奨キャラクター部品

- 比較表の後: `CharacterCallout` + `labomaru_chart_icon.webp`
- 注意点: `CharacterCallout` + `labomaru_worried_icon.webp`
- まとめ前: `CharacterGuideCard` + `duo_guide_half.webp`

### 内部リンク導線

- 土台記事へ戻すリンクを置く
- 関連する比較記事へ横移動させる
- 収益導線は、理解が進んだ後に自然に置く

### 注意点

- 料金、キャンペーン、在庫、スペックは最新確認が必要
- 最安だけを強調しすぎない
- 比較対象が多い場合は、先に比較軸を固定する
- 広告・PR導線は読者に分かる前提で扱う

## 3. ニュース記事 news

### 目的

新機能、新製品、話題の意味を生活者目線で整理し、基礎記事や選び方記事へつなげる。

例:

- `what-is-ai-smartphone`
- Apple Intelligence関連の話題解説
- 新製品、新機能、ガジェットトレンドの整理

### 想定読者

- ニュースを見たが、自分に関係あるか分からない人
- 新機能の実用性を知りたい人
- 買い替えや乗り換え判断に関係するか知りたい人

### 推奨構成

1. 何が話題なのか
2. 30秒でわかる結論
3. 何が変わるのか
4. 誰に関係あるのか
5. 便利な点
6. まだ微妙な点 / 注意点
7. 買う・選ぶ判断への影響
8. 関連する土台記事への導線
9. まとめ

### 使うべき表・チェックリスト

- 変わること / 変わらないこと
- 関係ある人 / まだ急がなくてよい人
- 発表内容と生活者への影響

### 推奨キャラクター部品

- 必要な場合のみ `CharacterCallout`
- AI・ガジェット説明では `himari_device_half.webp`
- 基礎記事への導線では `CharacterGuideCard`

### 内部リンク導線

- ニュース記事から土台記事へ送る
- 土台記事から比較・収益記事へつなげる
- 話題だけで終わらせず、選び方や判断軸へ落とし込む

### 注意点

- 最新情報は必ず確認する
- 未確定情報と確定情報を分ける
- 過度に煽らない
- 「すぐ買うべき」と断定しない
