# Search update notification

Production publishing runs in this order:

1. Cloudflare Pages deploy
2. production HTTP / strict verification
3. search notify (fail-soft)
4. independent X posting step

## Generated discovery files

- `/rss.xml`: newest 20 public articles, each with title, link, pubDate, and description.
- `/sitemap.xml`: conventional sitemap index alias.
- `/sitemap-0.xml`: URL entries generated by `@astrojs/sitemap`; article `lastmod` comes from `updated`, falling back to `pubDate`.
- `/robots.txt`: advertises `https://sumalabo.com/sitemap.xml`.
- `/{indexNowKey}.txt`: IndexNow host ownership proof. The public key and endpoint live in `config/search-notify.json`.

`scripts/automation/search-notify.mjs` checks the production RSS order and required fields, sitemap membership and lastmod, and key-file contents before posting the newly published article URL to the global IndexNow endpoint. HTTP 200 and 202 are accepted. Any failure is recorded as `warning` and never changes the publishing exit code.

## Google decision

Google retired the unauthenticated sitemap ping endpoint. The supported low-maintenance route is sitemap discovery from `robots.txt` plus accurate `lastmod`. Programmatic Search Console sitemap submission requires OAuth with the Webmasters scope; it is intentionally not added to the unattended runner until those credentials have an explicit lifecycle and least-privilege owner.
