# すまラボらしさ：記事の編集・比較・見せ方の共通ルール

制定：2026-11-03。正本はこの文書。月次商品比較の確認項目は [構造化ポリシー](../data/automation/sumalabo-editorial-identity.json) に対応する。

**「自分ならどれを選ぶか、その理由まで分かる」。難しい違いを、写真・比較表・ひまりとらぼまるのやり取りで、生活の判断に変える。** キャラクターを置くことや仕様を短くすることだけでは、すまラボらしさを満たさない。

## 1. 全記事に共通する約束

- 冒頭で「何の話か」「誰に関係するか」「結局どう選ぶか」を示す。今のままでよい人、買わなくてよい人も書く。
- 読者の疑問から比較軸を決める。「安い」「人気」「高性能」で終わらず、得する条件と困る条件を対にする。
- 公表仕様、第三者の実測、編集上の判断を分ける。未検証の実体験、架空の測定結果、根拠のない安全保証を作らない。
- 初心者向けの説明と、詳しく選びたい人の比較材料を両立する。読みやすさを理由に判断材料を削らない。
- 広告提携、写真の取得しやすさ、メーカーの国籍を推薦順位の代わりにしない。出典・確認日・条件を読者がたどれるようにする。

## 2. 商品比較の記事構成

1. 30秒で分かる結論と、買い替えを急がなくてよい人。
2. 最低3種類の用途別おすすめ。写真、対象者、確認済みの2軸以上の理由、妥協点、向かない人をセットにする。
3. 全10候補の写真付き早見表。価格・型番・主要仕様で全体をつかめるようにする。
4. **買う前に気になる違いの比較表**。メーカー・製造国、電池、旅行など、テーマ別に同じ10候補を横断して比較する。
5. 製品ごとの詳細、条件、出典、確認日。長い補足は開閉式でもよい。

早見表の3仕様は入口として使えるが、記事全体の比較項目を3つに制限しない。重要な違いが製品ごとの開閉欄にしかなく、10製品を何度も開かないと比べられない構成は不合格。同じ情報の長文を全セルへ戻すのではなく、比較表を目的別に分ける。

価格.comの人気売れ筋上位10は候補の入口であり、すまラボのおすすめ順ではない。元の10候補を保持し、用途外・確認不足の理由も見えるようにする。順位外で穴埋めしない。

## 3. 日本製・中国製を混同させない

共通表は「メーカーの拠点国・地域」「製造国」「国内の保証・問い合わせ」を分ける。例えば **日本メーカー／製造：中国** と **日本メーカー／製造：未確認** は別の情報であり、いずれも「日本製」と言い換えない。

- メーカーの拠点は公式会社情報で確認する。ブランドの発祥地、販売代理店の所在地と混同しない。
- 製造国は同じ型番・販売仕様の公式表示や製品ラベルを確認する。国旗だけ、社名、言語、価格、同シリーズの別製品から推定しない。
- 不明は「製造国：未確認（公式記載を確認できず）」など理由を添える。記載を見つけられないことを「メーカー非公表」と断定しない。
- 生産ロットや販売地域で異なる場合はその条件を添える。国籍だけで品質・危険性を判定せず、保証、回収情報、仕様を個別に比べる。

## 4. モバイルバッテリーで必ず見えるようにする項目

| 比較する表 | 全10候補で並べる項目 | 選ぶ判断へのつなげ方 |
|---|---|---|
| 基本性能・持ち歩き | 参考価格、mAh、Wh、重さ、単ポート出力、同時使用時の出力、入力・本体充電時間、ケーブル | 毎日持ち歩く軽さか、PC用の出力か。容量と重さの交換条件を示す |
| メーカー・電池・購入後 | メーカーの拠点、製造国、電池方式、PSE等の表示、回収告知、国内保証・窓口 | 日本メーカーと日本製を区別し、電池方式の違いと不明点を見分ける |
| 飛行機・旅行 | Wh、機内持ち込み、預け入れ、機内で本体を充電、機内で端末へ給電、個数・承認・保管条件、確認した航空会社・日付 | 持ち込めることと機内で使えることを区別する |

### 電池方式

「半固体」「準固体」「リン酸鉄リチウム」等は、同一型番のメーカー表記を確認し、メーカー公称と分かるように表示する。「半固体＝発火しない」「日本製＝安全」と書かない。リン酸鉄等の材料と電解質の状態は別の分類なので、排他的な一つの種類として決めつけない。メーカーがリチウムイオンとしか書いていない場合に、液系・半固体の別を推測しない。別モデルの新技術をブランド全体へ転用しない。

### 飛行機

更新のたびに国土交通省と対象航空会社の現行案内を確認する。数値・個数・承認条件を古い記事から固定で引き継がない。2026-11-03に確認した参照先は [国土交通省の新ルール](https://www.mlit.go.jp/report/press/kouku10_hh_000310.html) と [ANAの案内](https://www.ana.co.jp/ja/jp/guide/boarding-procedures/baggage/domestic/?menu=baggage-method)。持ち込みと機内での充電は別の制限であり、「飛行機OK」だけで済ませない。

- セルの表示は「条件付き可」「不可」「要確認」などの文字と条件を組み合わせる。○・×や色だけで意味を伝えない。
- 根拠はメーカーのWh表示と現行の輸送条件。mAhだけ、USB出力電圧を使った換算、半固体という名称だけで判定しない。必要なWh表示が確認できなければ「要確認」にする。
- 航空会社、適用便・地域、個数、承認の要否、端子保護・保管条件、適用日、確認日時、出典URLを記録する。他社便や国際線まで一律に許可しない。
- 国内外の回収対象・破損品等の条件も確認する。「条件付き可」は搭乗時の個別判断を保証する表現にしない。

## 5. 他のカテゴリでも「気になる違い」を選ぶ

全カテゴリでメーカー・製造国・保証を比較し、以下を追加する。バッテリーの比較軸を無関係なカテゴリへ無理に当てはめない。

| カテゴリ | 製品横断で見せる違い |
|---|---|
| USB-C充電器 | スマホ・PC適合、ポート構成、単独出力と同時配分、PD/PPSと必要ケーブル、重量、入力電圧・海外用プラグ、安全表示。乾電池用充電器は用途外の理由を明示 |
| イヤホン・ヘッドホン | 装着方式、重量、ANC・外音取込、同じ条件での電池持続時間、対応端末・コーデック、マルチポイント、通話機能。音質・装着感は未試聴と区別 |
| Wi-Fiルーター | WANとLAN各端子、Wi-Fi規格と6GHzの有無、対応端末、間取り・配置の条件、メッシュ互換、更新・サポート、追加費用。理論速度を実測にしない |
| 今後の家電 | 使う人数・部屋・設置条件、消耗品と継続費、手入れ、保証、苦手な使い方。その製品で購入後に困る違いを最低1群追加 |

## 6. 写真のない候補を完成扱いしない

全10候補に、同一型番・世代・容量を識別できる商品写真をそろえる。おすすめカードと比較表の両方で表示を確認する。**「写真未掲載」「画像準備中」や画像なし画像が残ったまま、完成・検品合格にしない。** 除外・保留候補も元の10候補として写真確認の対象にする。

まず既存の正規の画像・広告コンポーネントを使い、正確な型番で別の正規販売ページを探す。さらに必要なら掲載条件を満たす公式素材等を調べ、利用可能な経路を整える。画像が見つかることと転載・直リンクが許されることは別に確認する。写真の取得先URL、製品・画像の型番、確認日時、利用経路を内部に残す。

同じ基本モデルの色違いは、違いを写真の直下に明示できる場合のみ参考写真として使える。性能・形状が異なる世代違い、充電ケース単品、片耳単品、互換品、セット違いを本体写真の代用にしない。生成画像を実在製品の写真に見せない。写真を得やすい候補に順位を入れ替えない。

どうしても画像を用意できなければ、その更新は未完了として理由と試した取得先を残す。他の検品済みカテゴリは進められる。既に公開済みの記事は削除せず、欠落を保守課題として残す。写真なし公開を例外として認めるのはユーザーがその対象について明示した場合だけ。

## 7. ひまり・らぼまるを判断の案内役にする

ひまりは読者の疑問を拾い、らぼまるは条件・違い・妥協点を整理する。[正本仕様](../assets/characters/character-sheet.md) の役割と認識アンカーを守る。

商品比較では少なくとも冒頭の迷いと重要な比較表の読み方に、記事固有の短いやり取りを入れる。例えば、ひまり「日本メーカーなら日本製なの？」に対し、らぼまるが「メーカーの拠点と製造国は別の列で見よう」と表へつなぐ。会話は説明の一例であり、未確認の特定商品について言い切るために使わない。

末尾の汎用注意書き一つ、名前だけの吹き出し、キャラを置いただけの装飾では満たさない。会話の後に、読者がどの列を見てどう判断するか分かるようにする。実物の商品写真とキャラの解説は役割を分ける。既存の同題材・検品済みサムネイルは活用でき、ルール追加だけを理由に再生成しない。

## 8. 表の読みやすさ

- 一覧には短い数値・単位・判定・短い条件を置き、専門語にはその場で短い補足を付ける。空欄ではなく「非対応」「対象外」「未確認（理由）」を区別する。
- 写真、型番、参考価格、出典の対応を崩さない。参考価格と広告リンク先の販売価格、送料・ポイントの違いを明示する。
- 目的別の表や切り替えで、全10候補を同じ項目で比較できるようにする。重要項目を個別詳細だけに隠さない。初期表示の早見表だけで全比較が終わったように見せない。
- スマホでカード表示にしても、製品間で同じ順序・同じ見出しを保つ。比較軸を失う縦長の紹介文へ戻さない。
- 320px・390px・PC幅で実表示を確認する。ページ全体の横はみ出し、細かすぎる字、欠けた写真、押せない切り替えを残さない。色以外の判定文、見出し・表題、キーボード操作も確認する。

## 9. AI記事・キャンペーン記事への適用

AIを主軸にする選定は [記事選定ルール](scout-selection-policy.md) のまま継続する。注目ニュースを、AIが何を変えるか、日本の読者が何をできるか、どんな限界があるかへ翻訳する。企業名の固定リストにせず、話題の強さと具体的なAIの解説角度で選ぶ。性能指標はモデル版・評価条件・得意不得意、サービスは日本での利用可否・料金・制限を見せる。

携帯キャンペーンは還元額だけでなく、新規/MNP、対象プラン、申込経路、受取時期、維持条件、終了日を比較し、「この人なら対象／この条件なら対象外」を示す。更新頻度や自動公開の範囲は既存の各保守手順に従う。

## 10. 公開前の判定と既存記事への適用

月次更新は [保守手順](product-comparison-maintenance.md) と本ルールを両方満たす。自動チェックの合格だけを編集品質の合格に置き換えない。次の各項目に、実際に確認した箇所・出典・表示確認結果を残す。

| ID | 合格条件 |
|---|---|
| audience-and-choice | 誰に何がおすすめか、2軸以上の理由・妥協点・向かない条件がある |
| ten-candidates | 元の上位10候補を保持し、除外・保留の理由が見える |
| complete-photos | 10候補の正確な写真が表示され、未掲載・仮画像が残らない |
| cross-product-groups | カテゴリ必須項目をテーマ別に製品横断で比較できる |
| origin-separation | メーカーの拠点と製造国を分け、不明を推測していない |
| battery-claims | 該当カテゴリの電池方式は同一型番の公称で、不燃等を保証しない |
| travel-conditions | 該当カテゴリの飛行機判定を用途別に分け、現行公式条件とWhを照合している |
| character-guidance | ひまりの疑問とらぼまるの整理が具体的な選択につながる |
| evidence-and-freshness | 出典・型番・価格時点・未確認を区別し、当回の公式確認が済んでいる |
| responsive-comparison | スマホ・PCで写真、比較項目、切り替え、詳細を実表示確認している |

該当しない項目は理由付きで対象外とし、未調査を対象外にしない。privateな `logs/scout/product-comparisons/identity/<category-id>-check.json` に policyVersion、reviewedAt、articleSlug、checks（各id/status/evidence）、remainingIssues を保存する。statusはpass/fail/not_applicable。各証拠は確認した出典・記事位置・表示確認記録への参照とし、理由なしの自己申告だけでpassにしない。全必須項目がpassまたは正当な対象外となった更新だけを、従来の公式確認・記事ゲート・build・公開検証へ進める。人の追加承認待ちは設けない。

制定時点の生成器は「3仕様の早見表＋個別詳細」、写真は任意という旧仕様を含む。**この旧生成器をそのまま通しただけでは本ルールの合格にならない。** 次の記事更新では必要な構造化データ・生成器・表示を先に補い、上記を満たしてから公開する。既存の4記事を本ルールに適合済みとさかのぼって扱わず、写真欠落・比較群不足・汎用キャラ文を修正課題として残す。

適用実装では `scripts/automation/product-comparison-identity.mjs` が全10写真、カテゴリ別比較群、項目ごとの根拠と不明理由、Whに基づく飛行機の条件、記事固有の会話を構造検証する。これは事実の真偽や写真の実物一致を自動的に認定するものではない。公式原文との照合と実表示の検品を行い、その更新で確認した証拠に基づいて合否を記録する。
