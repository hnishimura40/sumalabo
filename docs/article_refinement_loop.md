# Article Refinement Loop（画像生成前の必須ループ）

最終更新: 2026-05-30

## 位置づけ

`CLAUDE.md` で定義した **Phase A 記事化フェーズ** の中で、**画像生成（スライド・サムネ）の前に必ず通す本文ブラッシュアップ・ファクトチェック・自己レビューのループ** を標準化したもの。

> **目的：記事本文・論点整理が未成熟なまま、スライド・サムネ生成や MDX 化へ進ませない。** スライド・サムネは「記事のおまけ」ではなく「記事理解の中核」。本文が定まらないと、そもそも何をスライド化するか決まらない。先に画像だけ作ると、汎用的な「すまラボっぽい絵」が量産されるだけで、記事の判断材料にならない。

関連:
- `CLAUDE.md` — 全体ポリシー
- `docs/user_directed_mode.md` — Phase A / B / C
- `docs/phase_a_input_flow.md` — Phase A 入口
- `docs/queue_states.md` — queue 状態

## 全体フロー（Phase A 内の位置）

```
[Phase A 入口チェック] → 対象確定レポート → 自動本処理開始
                                ↓
                ┌──────────────────────────────┐
                │   Article Refinement Loop    │ ← 画像生成の前に必ず通す
                │   (本ドキュメントの 4 段階)   │
                └──────────────────────────────┘
                                ↓
            article-ready-for-images 判定（基準クリア時のみ進行）
                                ↓
[スライド構成案策定] → [画像生成] → [画像ファクトチェック] → [必要なら再生成]
                                ↓
                [WebP 化] → [MDX 組み込み] → [build] → [PR Ready]
                                ↓
                  Human Review Checkpoint で停止
```

## 4 段階の Refinement Loop

### Stage 1: 調査・ファクトチェック

- 参考 URL（ユーザー指定）・公式情報・主要報道を確認
- 価格・対象国・提供時期・未確定情報の所在を明示
- **公式発表と報道ベースを必ず分ける**
- 次の 3 つに分類して整理：

| 分類 | 意味 | 扱い |
|---|---|---|
| **facts** | 公式発表で裏取り済み | 本文で断定してよい |
| **claims** | 報道・解説・関係者発言 | 「と報じられている」など距離感を残す |
| **uncertain_points** | 未確定 / 日本未提供 / テスト段階 | 「未確定」と明示、断定しない |

### Stage 2: すまラボ向け論点整理

> **記事の主軸（2026-05-31 補正）**: すまラボ記事の中心は **デジタルニュースをやさしく噛み砕いて説明すること**。「あなたに関係ある？」「課金すべき？」のような読者判断は **補助**であって主軸ではない。下記の (1)〜(4)（何が起きた / なぜ話題 / 誤解されやすい点 / 確定・未確定の整理 / 意味づけ）を記事の中心に置き、(5) の読者判断は記事の後ろ寄りに 1〜2 ブロックだけ添える。

次を 1 メッセージで言語化する：

1. **何が起きたのか / 何が変わるのか**（事実の核）
2. **なぜ話題なのか**（意味・背景）/ **確定情報と未確定情報の整理**（事実 / 報道ベース / 未確定）
3. **どこが誤解されやすいか**（強い見出しに引きずられそうな点）
4. **ニュースの意味づけ**（読者の生活・選択にとって何を意味するか）
5. （補助）**誰に関係があるか / 今すぐ動くべきか様子見か**（記事の後ろ寄りに短く。課金診断に寄せない）

### Stage 3: 本文ドラフト作成

- lead-first / 先に結論
- 文字だらけにしない（box / table / check-list / decision-guide-panel で割る）
- 表・チェックリスト・判断ガイドを使う
- 「普通の人」「すまほん」「smhn」「元記事」「ここから本文」「初稿」「最終稿」は **0 件必須**
- スライドで語る部分と本文で補う部分を切り分けたメモを残す（次の構成案策定に使う）

### Stage 4: 自己レビュー（最低 2 回・必要なら 3 回）

#### Pass 1 — メタ表現・煽り・誤解・断定の点検

- メタ表現（「この記事では」「次の章で」「ここから本文」など）が残っていないか
- 煽りすぎていないか（「絶対」「100％」「必見」「全部」など）
- 誤解を招く見出しや説明がないか（「Instagram 全部有料化」など）
- 断定しすぎていないか（噂・テスト段階を断定していないか）
- 禁則表現の grep（普通の人 / すまほん / smhn / ここから本文 / 最終稿 / 初稿 / 元記事）

#### Pass 2 — すまラボらしさ・判断材料・スライド化論点の点検

- すまラボらしく、読者が「自分はどう判断すればいいか」分かるか
- ただのニュース要約で終わっていないか
- 料金・対応国・未確定情報の扱いが正しいか（Stage 1 の分類と整合）
- **スライド化すべき論点が明確か**（次のステップでスライド構成案に落とせるか）

#### Pass 3（必要時）— 事実・数値・出典の再チェック

- 事実・数値の最終確認
- 参考情報欄に入れるべきソースの確認
- 引用・出典の言い回し（hedge の強さ）が適切か

#### 修正版本文の作成

自己レビューの指摘を反映して本文を更新。**指摘が残っているうちは画像生成に進まない**。

## article-ready-for-images 判定

次の 6 つを **すべて** 満たしたときだけ、スライド構成案策定 → 画像生成へ進む。

| チェック | 確認方法 |
|---|---|
| ① 記事の結論が明確 | 「先に結論」セクションが 1 文 + 短い bullet で書けている |
| ② 読者の判断材料が明確 | 「向いている人 / 待つべき人」「3 つの質問」など意思決定 UI がある |
| ③ 誤解されやすい点が整理済み | 強い見出しに引きずられそうな箇所に hedge / 注記がある |
| ④ 事実・未確定・予想が分かれている | Stage 1 の facts / claims / uncertain_points が文中で区別されている |
| ⑤ 禁則表現 0 件 | grep で 0 hits |
| ⑥ スライド化する論点が決まっている | 「この 6〜8 枚をスライドにする」という構成案リストがある |

> このうち 1 つでも欠けていれば、画像生成へ進まずに Refinement Loop に戻る。

## スライド構成案の提示形式

`article-ready-for-images` を満たしたら、画像生成の前に **スライド構成案** をユーザー（or ChatGPT 経由の議論相手）に提示する。

```
## スライド構成案（N 枚 + サムネ 1 枚）

### スライド一覧
1. [タイトル] — [このスライドで読者が持ち帰る要点]
   - mustInclude: [必ず含める事実 1〜3 個]
   - characterRole: ひまり=[役割] / らぼまる=[役割]
   - props: [比較ボード / 注意カード / etc.]
2. ...

### サムネ案
- 大見出し候補: [強くない、誤解を招かない短い文 1〜3 案]
- 構図: [キャラ 2 名が何の道具で何を整理しているか]
- 避ける: [実在ロゴ / 公式画像コピー / 煽り表現]

### 同じ ChatGPT チャットで進める流れ
1. このメッセージで構成案を確定
2. 次のメッセージで himari-base.png / labomaru-base.png を添付
3. 続けて Slide 1 から順に画像生成リクエスト
4. 各画像生成後にファクトチェック → 必要なら再生成
```

## スライド・サムネ生成（article-ready-for-images 後）

- **`article-ready-for-images` 判定を通る前は実行しない**
- **同じ ChatGPT チャット内で**、記事の議論 → 修正 → 画像生成までつなげる（チャットを分断しない）
- スライド構成案を確定した後に、Slide 1 → Slide 2 → ... → サムネ の順で 1 枚ずつ生成
- 各画像生成後に **必ずファクトチェック**：価格・固有名詞・対象国・対象機能・hedge 表現が正しいか
- 1 枚でも事実誤り・置物化・誤読リスクがあれば、その 1 枚を再生成（最低 1 ラウンドは見直す）

---

## ChatGPT 同一チャット運用の利点

- プロジェクト「すまラボ台本」のシステム指示が継承される
- 記事の議論で積み上げた論点・hedge 表現がスライド・サムネに引き継がれる
- 1 つのチャットの履歴を見るだけで Refinement Loop の経緯が再現できる
- スライド再生成時に「論点に戻る」コストが低い

### 別チャットを開いてはいけない場合

- 記事のドラフトを別チャットで作って、画像生成だけ別チャットで頼む
- 画像だけ「すまラボっぽい絵」をジェネリックに作る
- 記事本文の確定前にサムネだけ先に作る

## 失敗パターンと回避

| 失敗パターン | 何が問題か | 回避 |
|---|---|---|
| 本文ドラフトなしで画像生成リクエスト | スライドが「何の話か」決まらないので汎用的になる | Refinement Loop 通過必須 |
| サムネを先に作る | 記事の結論未確定なのに煽り見出しが出る | Stage 4 通過後にだけ作る |
| 別チャットで本文だけ書いて画像は別チャット | 論点と画像が乖離する | 同一チャット運用 |
| 自己レビュー 1 回で進める | メタ表現や煽り見出しが残る | 最低 2 回。判断に迷えば 3 回 |
| facts / claims / uncertain を分けないまま画像化 | 噂を断定する画像が出る | Stage 1 で必ず分類 |

## 関連 queue 状態

詳細: `docs/queue_states.md`

| status | 意味 |
|---|---|
| `article_generated` | 本文ドラフトが書けた直後（自己レビュー前） |
| `article_ready_for_images` | Refinement Loop を通過し、画像生成に進める状態 |
| `review_waiting` | スライド・サムネ含めて PR 作成完了。Checkpoint 待ち |
| `blocked_image_generation_unavailable` | 画像生成経路（Chrome MCP）が通らず Phase A 停止 |

> **`article_ready_for_images` を通過していない状態でスライド・サムネ生成に進むことは禁止。**
