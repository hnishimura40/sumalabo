# AI記事の型 v2（ニュースをかみくだく）— 2026-11-04

`docs/sumalabo-editorial-identity.md` §9「AI記事・キャンペーン記事への適用」の具体化。AIを主軸にした毎日1本の記事に適用する。Scoutの選定ルール（`scout-selection-policy.md`）は変えない。変えるのは記事の構造と、各ブロックの材料。

## 0. なぜ変えるか

2026-11-04に公開済みのAI記事2本（Alexa+早期アクセス、Gemini Notebook教科書）を確認した共通の癖：

- 「図解」が1記事に8枚あり、各図に「図のポイント」2行。同じ内容を図・本文・ポイントで3回書いている
- 「先に結論」「30秒サマリー」「すまラボまとめ」で要点が3回出る
- 出典が末尾「参考情報」のみ。本文の各主張がどの発表に基づくかがその場で分からない
- 読者の行動が「確認してください」で終わり、何を確認してどうなったら何をするかがない
- 比較記事への導線がなく、収益線がゼロ
- 見出しが「3,000円」を立て、本文が「今は無料」と逆を向く

未確定を未確定と書く、実機未検証と書く、という正直さは維持する。

## 1. 構造（この順で固定）

| 順 | ブロック | 必須 | 材料 |
|---|---|---|---|
| 1 | 見出し | ○ | 読者の質問に答える文。見出しが立てる数字・主張と、本文冒頭の答えが同じ向きであること |
| 2 | 答え | ○ | 1〜2文で答え切る。同じ箱に根拠の出典バッジ（発表元＋日付）と確認日 |
| 3 | あなたの場合は？ | ○ | 関係あり／様子見／関係なし の3分岐。各分岐に「条件」「その人が今やること（または何もしない）」 |
| 4 | 何が変わった／日本でできる／まだできない | ○ | 3カラム。各カラムに出典バッジ。「まだできない」には未発表・未確定・対象外を入れる |
| 5 | 図 | 1枚まで | 一番誤解されやすい1点だけ。キャプション1行。「図のポイント」は書かない |
| 6 | ひまり・らぼまる | ○ 1往復 | ひまりが典型的な誤解を言い、らぼまるが訂正して「今日決めることは何か」で締める |
| 7 | すまラボの見立て | 条件付き | 「確定情報ではない」の明示付きで編集部の読みを1段落。生成規則は§3 |
| 8 | 使うなら次にやること | ○ 3つ | 「確認してください」ではなく、確認する対象・順番・どうなったら何をするか |
| 9 | この話に関係する道具 | ○ 1〜2枚 | 月次比較記事の「今月の1台」カード。記事タグ→カテゴリの対応表（§4）で自動選定 |
| 10 | 出典と更新履歴 | ○ | 出典は発表元・日付・何の根拠かを1行で。更新履歴は日付ごとに「何を確認し、変更があったか」 |

廃止：30秒サマリー（3・4が代わり）、先に結論（2が代わり）、すまラボまとめ（2と重複）、図のポイント、2枚目以降の図解。

## 2. 出典バッジ

- 本文で主張を置く各ブロック（2・4・7）に、`発表元 日付` の形のバッジを置く。例：`Amazon公式発表 2026-10-29`、`Googleヘルプ 確認 2026-10-31`
- 一次情報（発表元の公式ページ）を優先。報道は「参考」として10に置き、2・4の根拠には使わない
- バッジの日付は、発表日または確認日のどちらかを明示する（「確認」を付ける）

## 3. 「すまラボの見立て」の生成規則（無人運用）

見立ては編集判断なので、人の文章ではなく、**未確定項目の型から定型で導く**。以下の表に当てはまる場合だけ出力し、当てはまらなければブロックごと省略する。

| 未確定項目の組み合わせ | 見立ての定型 |
|---|---|
| 終了日未発表 ＋ 主要機能が「今後提供予定」 | 「課金や制限が始まるのは機能が出そろってからで、急いで判断する理由は今のところない」 |
| 日本の提供時期が未発表 ＋ 本体サービスは日本対応 | 「日本で使える状態になってから判断すれば足りる。今は自分の画面で表示を確認する段階」 |
| 価格のみ発表 ＋ 提供範囲が未発表 | 「価格だけが先に出た段階。対象者が決まるまで比較の相手がない」 |
| 公式が「一部機種は対象外」＋機種名未公表 | 「自分の機種が対象か分かるまで、周辺機器を買い足す理由はない」 |

- 見立てには必ず「公式発表から編集部が読んだこと。確定情報ではありません」を付ける
- 根拠として使った未確定項目を、見立ての文中に列挙する（上の例では「順次案内」「終了日未発表」「外部連携は今後」）
- 定型に当てはまらないときに自由生成しない。Hiroが手で書いた見立てがある場合はそれを優先して表示する

## 4. 「関係する道具」の対応表

記事のタグ（Scoutが付ける）から、月次比較のカテゴリを引く。カテゴリが未作成なら、そのカードは出さない（空カードや準備中は禁止）。

| 記事タグ | 比較カテゴリ |
|---|---|
| スマートスピーカー、音声アシスタント、スマートホーム | smart-remote（未作成）、wifi-router |
| 生成AIサービス（Gemini・ChatGPT・Claude等）の新機能 | usb-charger、power-bank（スマホで使う前提）／ PC・タブレット比較があればそれ |
| 学習・ノート系AI | タブレット比較（未作成）／ なければ出さない |
| 自動運転・モビリティ | なし（出さない） |
| スマホ新機種・価格 | smartphone-30k（既存記事を月次化した場合）、usb-charger |
| AIモデルの提供条件・料金 | なし。代わりに「AIモデルの選び方」等の既存ガイドへ |

カードには比較記事の「今月の1台」の写真・断定見出し・号数を出す。写真は比較記事側の検品済み画像を使う。

## 5. 長さと図

- 本文は2,000〜2,800字を目安（現行は約3,000字＋図8枚）
- 図は1枚まで。図が不要な話題では0枚でよい
- PC幅で本文幅860px、スマホ320/390pxで横はみ出しなし。3カラムはスマホで縦積み

## 6. 見出しのルール

- 読者が検索窓に打つ疑問の形にする（「〜は誰が使える？」「〜はいつから必要？」「〜は日本で使える？」）
- 見出しに数字を出すなら、答えブロックの1文目にその数字の条件を書く（「3,000円」→「終了後の非会員だけ」）
- 見出しと答えが逆を向く記事は検品で不合格（下のチェックID `headline-answer-align`）

## 7. チェックID（公開前）

| ID | 合格条件 |
|---|---|
| headline-answer-align | 見出しの数字・主張と、答えブロックの1文目が同じ向き |
| answer-with-source | 答えブロックに出典バッジと確認日がある |
| three-way-split | 「あなたの場合」が3分岐で、各分岐に条件と行動がある |
| source-badges | 4の各カラムに出典バッジがあり、一次情報が根拠になっている |
| one-figure | 図は1枚以下で「図のポイント」がない |
| no-duplicate-summary | 30秒サマリー・先に結論・まとめが存在しない |
| next-actions | 「次にやること」が3つで、各項目に確認対象と順番がある |
| tool-cards | 対応表にカテゴリがある話題では道具カードが出ている。未作成カテゴリのカードは出ていない |
| stance-rule | 見立てがある場合、§3の定型に当てはまり、未確定項目が列挙され、注記がある |
| changelog | 更新履歴に公開日と、更新ごとの確認内容がある |
