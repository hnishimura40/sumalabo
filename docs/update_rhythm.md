# M4: 更新リズム（公開・更新の運用ルール）

すまラボの「何を・どの頻度で・どう更新するか」を固定する文書。

## 記事の3レーン

| レーン | 頻度 | テンプレ | ソース |
|---|---|---|---|
| ニュース記事（流入） | testMode/無人runの自動運転（1晩1本まで） | A ニュース解説 / B 続報・経緯型 | scout（RSS収集→採点→autoPick） |
| **資産記事（evergreen）** | **月1本** | **C 比較・選び方型（結論の表を先に）** | `drafts/ideas-evergreen.md` の上から順に消化 |
| 既存記事の更新 | 随時（事実が動いたとき） | 元記事のまま | 鮮度チェック（7日ルール）・公式変更の検知 |

## 資産記事（月1本・テンプレC）の運用ルール

1. **毎月第1週**に `drafts/ideas-evergreen.md` から1本選ぶ（上から順が原則。時事と噛み合うものがあれば入れ替え可）
2. テンプレC（比較・選び方型）で作る: **結論の表 or カードを最初に**置き、本文はその根拠と注意点
3. ニュース記事と同じ品質ゲートを通す（gate full / 画像ファクトチェック / 禁則）
4. 公開後は `ideas-evergreen.md` の該当行に公開URLを追記して消化管理
5. **月次メンテ**: 公開済み資産記事は毎月1回、事実（価格・提供条件）を公式で見直し、変更があれば本文修正 + frontmatter `updated` を更新（sitemap の lastmod が動き、検索エンジンに更新が伝わる）

## 陳腐化を防ぐ書き方（資産記事共通）

- 具体的な価格・日付は「調査時点」を明記し、本文は原理・考え方を主役にする
- 「公式ページで最新確認」の注記＋公式リンクを必ず置く
- 機種名・バージョン名に依存する記述は表に隔離し、本文は普遍的に書く
