# すまラボ 一般読者向け「噛み砕き」生成規則

この文書は記事生成・レビュー・MDX化・公開前検査が共通で参照する正本です。AIの役割は「専門ニュースの要約」ではなく、**その分野を初めて知る人へ説明する編集者**です。

## 生成前の読者翻訳設計

Editorial Selectionで事実を確定した後、本文を書く前に次を `## 読者翻訳設計` として内部成果物へ記録します。これは公開本文へコピーしません。

- 主題の一言説明: これは何の話かを、固有名詞だけに頼らず一文で書く
- 関係がある人: 今回の変化で行動や判断が変わる人
- あまり関係がない人: 今すぐ判断を変えなくてよい人
- 専門用語: `専門語 → 普通の日本語による短い説明` の形式で列挙する
- 事実から言えること / 言えないこと: たとえや言い換えで事実を広げないための境界

本文の思考順序は、(1)これは何か、(2)自分に関係するか、(3)何が変わったか、(4)何が便利か、(5)注意点、(6)詳しい情報、です。専門情報から始めません。

## 30秒で分かる

既存の4項目を使う記事では、要点を `Summary30` 内の4つの `li` に書きます。公開文に「これは何？」「誰に関係ある？」などの固定ラベルを繰り返す必要はありません。先に答えを置くなど、題材に合う順で並べ、各項目の役割は `data-summary-point` で示します。

| 値 | 読者に届ける情報 |
| --- | --- |
| subject | 主題、比較対象、仕組み |
| context | 何が起きたか、どんな条件で比べたか |
| audience | どの人の判断が変わるか |
| answer | 結論、または最初に見る場所 |

各項目には読者に伝わる一文を置きます。たとえば端末比較では `<li data-summary-point="answer">端末を手元に残すなら「乗り換え一括」の列から見ます。</li>` と書けます。見出しを添える場合も題材固有の短い言葉にします。従来の固定ラベルは既存記事の検品に使えます。

本文前半で、判断に関係する条件と影響が薄い条件を具体的に書きます。自然な段落にする場合は、該当する文章を `<p data-reader-scope="relevant">…</p>` と `<p data-reader-scope="unaffected">…</p>` に入れます。

## 専門用語

- 専門用語は初出の同じ文か直後の一文で、普通の日本語に説明する。
- 専門語を別の専門語で説明しない。
- 固有機能名は「何を助ける機能か」を添える。
- 必要なら日常のたとえを一つ使う。ただし「たとえると」と明示し、事実と混ぜない。
- 「つまりどういうこと？」「ざっくり言えば」は難しい概念の後だけに使い、定型句として乱用しない。

## 標準構成

ニュース記事では、次の論点を題材に応じて組み合わせます。公開見出しには具体的な違いや疑問を置き、冒頭と同じ内容のまとめは省きます。

1. 30秒で分かる
2. そもそも○○って何？
3. あなたに関係ある？（関係がある人 / あまり関係がない人）
4. 今回何が変わった？
5. 何がうれしい？
6. 注意点
7. どんな人におすすめ？
8. もう少し詳しく知りたい人向け
9. すまラボまとめ

最初の一文は、その記事でしか言えないことから始めます。金額や日付が判断を変えるなら、条件と一緒に出します。見出し直後や記事末尾が冒頭の言い直しになったときはまとめ、本文には理由・例外・次に見る箇所を置きます。見出しは具体的な疑問や違いを題名にし、句調は話の流れに合わせます。最後に音読し、同じ前置き、三段の言い換え、根拠のない体験談や断言を除きます。

## キャラクター

ひまり・らぼまるは、読者が実際に抱く「それは何？」「私に関係ある？」「結局何が便利？」を質問・回答する役目です。専門知識を披露し合う会話や本文の言い直しだけにしません。

## 事実と内部情報の分離

Research Passで事実・主張・不明点を分け、その後に一般向け説明へ変換します。不明点は断定しません。

スカウト情報、生成指示、コピー指示、自動公開・veto操作、内部メモ、system prompt等は内部成果物だけに置き、公開MDXへ出しません。`system` や `prompt` の単語自体を禁止するのではなく、編集工程の操作指示になっている文脈を公開前ゲートで遮断します。
