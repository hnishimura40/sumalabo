# 記事の表：ライト／ダーク検品（2026-11-23）

AI記事・ニュース・商品比較・携帯キャンペーンを含む、表があるすべての記事に適用する。新規作成、既存記事更新、表コンポーネントや共通CSS変更のときに確認する。ユーザーの個別の見た目指定を優先する。

## 作るときのルール

- 標準は背景の塗りつぶしなし、ライトでは黒文字。見出し・合計・注意事項は罫線・太字・余白・明示ラベルで区別する。色帯や交互の塗りつぶしで区別しない。
- ダークでは、背景に合うテーマの本文色へ切り替える。標準の文字色は `var(--article-table-ink)` を使う。この変数は `src/styles/global.css` でライトは黒、ダークは `var(--fg)` に定義している。コンポーネント固有の同等のテーマ変数も使える。
- `<table>` だけでなく `th`・`td`・見出し・リンク・強調・単位・注記を確認する。親の色を直しても、子の固定色が残っていれば直す。
- 表内のインライン指定で `#000`・`black`・`#fff`・`white`・固定の `rgb()` などを使わない。背景も固定の白／黒にしない。継承、透明、テーマ変数を使う。
- CSS変数の名前だけで安全と判断しない。定義とダークでの切り替えを確認する。透明な背景は、セルから祖先へたどった実際の下地と組み合わせて判定する。

## 公開前の機械検査

1. `npm run qa:table-theme` で記事ソースとビルド済みHTMLを走査する。表・セル・表内の子要素の固定インライン配色は不合格。コード例やコメント、表の外の配色は対象外。
2. 既存の記事ゲートのdraftで最終本文、workspace/fullでMDXとビルド済みHTML、auditで全記事ソースを同じ基準で検査する。ビルド後にも、全記事HTMLの検査を自動実行する。
3. 正式ブラウザのプレビューで、ライト／ダークを切り替えて実表示を測る。通常文字は4.5:1以上、大きい文字（24px以上、または18.67px以上の太字）は3:1以上を下限にする。写真や画像内の表は別に目視し、このHTML検査で合格したことにしない。
4. PCとスマホ（少なくとも390px、商品比較は既存ルールの320pxも）で、文字欠け・過度な改行・ページ全体の横はみ出しを確認する。表内の横スクロールは許容する。スクロール先の列も読む。
5. 折りたたみ、テーマタブ、絞り込みがある表は展開・切り替えた状態も確認する。リンク・補足・合計・注意欄を含め、色だけで意味を伝えない。

静的検査はCSSの継承・変数解決・実コントラストを計算しない。静的検査の成功を、ブラウザでの測定や目視検品の成功と報告しない。人の確認・承認待ちは追加せず、既存の承認範囲内で修正・再検品・公開確認まで進める。
