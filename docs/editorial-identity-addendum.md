# すまラボらしさ 追記：編集部の3枠・見せる順序・判定の機械化（2026-11-04）

正本 `docs/sumalabo-editorial-identity.md`（制定 2026-11-03）への追記。既存の各節は削除せず、本追記が優先する箇所を明記する。月次商品比較の構造化ポリシー `data/automation/sumalabo-editorial-identity.json` と、カテゴリ別の判定条件 `data/automation/product-comparison-picks.json`（新設）に対応する。

## 0. なぜ追記するか

制定時のルールは「間違ったことを書かない」ための網としては機能したが、「何を選んだか」を言わせる仕組みがなかった。§1「公表仕様・第三者実測・編集上の判断を分ける」は分類の指示であり、編集判断を必ず出力せよとは書いていない。結果として、全10候補を同じ重さで並べた「全部正しくて何も言っていない」記事が生成された。本追記は、判断を**人の好みではなく確認済みの軸の条件判定**として必ず出力させ、同時に見せる順序を規定する。

## 1. 編集部の3枠（§2の2項目目「最低3種類の用途別おすすめ」を置き換える）

全カテゴリで、次の3枠を必ず出力する。枠に入れる判定は `product-comparison-picks.json` の条件で機械的に行い、人の追加承認は設けない。

| 枠 | 判定 | 決め手の生成 |
|---|---|---|
| **とにかく安く** | 必須軸をすべて満たす候補のうち最安 | 「10候補で最安」＋それでも満たす必須軸を2つ、数値付きで |
| **迷ったらこれ** | 候補数が最も多い「段」の中で、必須軸＋上位軸を満たす候補のうち最安 | 「この段で必須軸と上位軸を満たす最安」＋上位軸の値 |
| **カテゴリ固有枠** | カテゴリ設定で定義（例：ルーター＝最上位の段で6GHz帯ありの最安、イヤホン＝カナル型以外の各形の代表） | 設定の `claimTemplate` に従う |

- **段**：カテゴリ設定の `segmentAxis` で決める読者側の条件（ルーター＝回線入口WAN、イヤホン＝装着方式、バッテリー＝容量帯 など）。読者が自分の段を先に選べるようにする。
- **必須軸**：満たさなければどの枠にも入れない軸。全カテゴリ共通で「国内の保証・問い合わせ窓口あり」を含める。
- **上位軸**：「迷ったらこれ」と「とにかく安く」が同じ製品にならないための1軸。確認済み（verified）の値でのみ判定し、未確認の候補は上位軸を満たさない扱いにする。
- 条件を満たす候補がない枠は「今月は該当なし」と理由を書く。候補外で埋めない。
- **次点**：各枠の条件を満たす2番目。枠との差を軸1つと価格差で1文にする。なければ「次点なし」。
- 判定に使えるのは `status=verified` の値だけ。`unknown` は不利に扱う（満たさない）が、推薦理由に「未確認だから劣る」とは書かない。
- 決め手の文に「人気」「高性能」「コスパ」「安心」を使わない（§2既存の規定と同じ）。
- 枠の名前と決め手の文型は、既存の「ペルソナ別おすすめ」より前に置く。ペルソナ別は、3枠の深掘り内の「向いている人」として残す。

## 2. 見せる順序（§2の記事構成を置き換える）

1. **30秒で分かる結論**：「誰に関係ある／今のままでよい人／まず見ること（段の決め方）／結局どれ（3枠の名前）」の4点。「何があった？」は速報記事の型であり、比較記事には入れない。
2. **今月の1台（迷ったらこれ）**：写真大、断定の見出し（製品名より先に読者の得を一文）、バッジ「すまラボ 今月の1台 YYYY.MM」、○○✕の3行、同じ段の中での位置（価格・主要軸2つのバー、数値は公式仕様）、価格ボタン、らぼまるの「ココに差が」1つ。
3. **残り2枠**：同じ型を小さく。各枠に次点を1行。
4. **段×価格のマップ**：縦＝段、横＝参考最安値（対数）。3枠だけ色を付ける。スマホ幅では段ごとのチップ一覧に切り替える。
5. **残りの候補の達成表**：順位を付けない。必須軸・上位軸の○✕と「外れた理由」「こんな人に」を横に並べる。保留・用途外もここに理由付きで残す。
6. **全候補のテーマ別比較表**（既存§2の4項目目）：先頭タブを「メーカーの拠点・製造国・国内窓口」にする。
7. **選び方の脚注**：候補の取得元と日付、必須軸、各枠の条件、やっていないこと（実機測定・試用・広告提携による順位変更）。出典一覧は折りたたみ。

既存の「10製品の写真付き早見表」は廃止する。写真は2・3・5で全候補分を表示するので、§6「写真のない候補を完成扱いしない」はそのまま適用される。§1「読みやすさを理由に判断材料を削らない」は維持するが、**初期表示で全候補のフルスペック表を見せない**。判断材料は6に全部あり、順序だけを規定する。

## 3. 製造国のエスカレーション（§3に追加）

- 製造国が未確認の候補が**4台以上**ある月は、公開前に正規販売ページのラベル写真・取扱説明書PDF・公式FAQを候補ごとに個別確認する工程を必須にする。確認先URLと結果を `comparisonFacts.manufactureCountry.sources` に残す。
- それでも未確認なら、理由を「公式記載を確認できず」「販売地域・ロットで異なる」「取説に記載なし」のいずれかに分類して残す。
- 「国内の保証・問い合わせ窓口」は全候補で必ず確定させる（公式会社情報で確認できる）。製造国が揃わない月でも、この列で購入後の差は比べられる。
- 記事本文に「日本メーカー＝日本製ではない」の注記を、製造国列の直下に1回入れる。

## 4. 重複除去（§8に追加）

- 同一軸で同じ文言が**3候補以上**に並ぶ場合、その軸は表から外し、「全候補共通の注意」として表の直下に1回だけ書く。表に残すのは差がある項目だけ。
- 「先に結論」「図解」「まとめ」で同じ要点を3回書かない。結論は冒頭の30秒まとめ1回、末尾は「選び方の脚注」に置き換える。

## 5. 30秒サマリーの型（比較記事用）

速報記事の「これは何／何があった／誰に関係／結局どう」ではなく、「誰に関係ある／今のままでよい人／まず見ること／結局どれ」の4点。「結局どれ」には3枠の製品名を入れる。

## 6. 価格ボタン（収益の決断点）

- 3枠の各カードと深掘りに、楽天・Amazonの両方のボタンを置く。ボタン文言は「楽天で見る ▶ ○○円〜（広告）」のように参考最安値を併記する。
- 達成表の各行にも小さく価格リンクを置く。
- 価格の時点と、リンク先価格との差異の注記は既存§8のまま。

## 7. 「人」を入れる装置（買わない前提で）

- 実機は購入・試用しない。その代わり「選び方の脚注」の「やっていないこと」に、実機測定・試用をしていないことと、広告提携で枠を変えないことを明記する。これはすまラボの透明性の宣言として機能させる。
- らぼまるの「ココに差が」は各枠に1つ。内容は確認済みの公式仕様から言えることに限る（§7の既存規定）。
- 編集部の利用環境（回線速度・使用中の機種など、確認済みの事実）を「迷ったらこれ」の近くに1文入れてよい。推測や感想は書かない。

## 8. チェックIDの追加（§10の表に追加）

| ID | 合格条件 |
|---|---|
| editorial-picks | 3枠すべてが埋まっている（または該当なしの理由がある）。決め手がverified軸2つ以上と数値で書かれ、禁止語を含まない |
| reading-order | 今月の1台が表より前にあり、初期表示に全候補のフルスペック表が出ていない。早見表が存在しない |
| no-repeated-cells | 同一文言が3候補以上に並ぶ行が表に残っていない |
| origin-escalation | 製造国未確認が4台以上の月に、候補別の個別確認記録がある。国内窓口は全候補で確定 |
| price-buttons | 3枠の各カードと深掘りに楽天・Amazonの両ボタンがあり、参考最安値が併記されている |
| mobile-overflow | 320/390px幅で、ナビ・表・カードに横はみ出しがなく、表は横スクロール箱に入り、製品名列が固定されている。マップはチップ表示に切り替わる |

## 9. 既知のスマホ表示バグ（2026-11-04に390px幅で確認）

- 早見表の製品名列が約40px幅になり1文字ずつ折り返し、右側が空の領域になる。行の `overflow:hidden` で中身も切れる。→ 早見表の廃止で解消。
- サイトナビの右端が切れ、続きがあると分からない。→ 横スクロール＋右端フェード（`mask-image`）に変更。
- 全高が390px幅で約20,000px。→ 見せる順序の変更と早見表廃止で、PC約5,000px・スマホ約8,500pxを目安にする。
